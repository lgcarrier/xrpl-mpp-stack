# Ripple XRPL MPP SDK cross-language fixtures

`fixtures.json` is generated by the TypeScript implementation in
[`ripple/xrpl-mpp-sdk`](https://github.com/ripple/xrpl-mpp-sdk), pinned to
commit `6907484c92d217da406e2f3d7b5e6587703c6ea8`. CI installs that checkout with
its locked `pnpm@10.19.0` dependency graph, runs `generate-fixtures.ts` from
inside the checkout, and requires byte-for-byte equality with the committed
golden file.

The offline Python regression validates the same golden values with
`xrpl-mpp-core`. Coverage includes charge and session method/request schemas,
transaction and hash charge payloads, open/voucher/close PayChannel payloads,
core-only Ripple-style receipts and their exact references, and the shared
challenge-to-invoice-ID derivation.

To regenerate intentionally:

```bash
git clone https://github.com/ripple/xrpl-mpp-sdk /tmp/xrpl-mpp-sdk
git -C /tmp/xrpl-mpp-sdk checkout 6907484c92d217da406e2f3d7b5e6587703c6ea8
cd /tmp/xrpl-mpp-sdk
npx pnpm@10.19.0 install --frozen-lockfile
cp /path/to/xrpl-mpp-stack/conformance/ripple-xrpl-sdk/generate-fixtures.ts scripts/xrpl-mpp-stack-generate-fixtures.ts
RIPPLE_XRPL_MPP_SDK_REF=6907484c92d217da406e2f3d7b5e6587703c6ea8 npx pnpm@10.19.0 exec tsx scripts/xrpl-mpp-stack-generate-fixtures.ts
```

This is deterministic wire-contract interoperation, not a live XRPL test. The
fixture blobs and claim signatures are schema-valid sentinels; ledger
submission, cryptographic voucher verification, and Testnet behavior remain
covered by native and opt-in live tests.
